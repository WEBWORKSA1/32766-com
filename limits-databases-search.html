Databases & search engine limits

Data stores limit bytes. In UTF-8 an English letter is 1 byte, an accented letter 2, most Asian scripts 3 and emoji 4 — so a limit that's generous for English can be tight for multilingual data. The most famous of these is the one this site is named after: Apache Lucene's 32,766-byte maximum for a single indexed term.

The errors you'll see

  • Elasticsearch/OpenSearch: Document contains at least one immense term … longer than the max length 32766 / bytes can be at most 32766 in length.
  • PostgreSQL: index row size … exceeds btree version 4 maximum 2704.
  • MySQL: Specified key was too long; max key length is 3072 bytes or Row size too large.
  • SQL Server: warnings that an index key exceeds 900 (clustered) or 1,700 (nonclustered) bytes.

Patterns that fix most of them

  • Don't index long free text as an exact-match value; index a hash (MD5/SHA-256) or a prefix instead.
  • Use full-text fields for long text and keep exact-match fields short.
  • Validate byte length at the API boundary, not after a failed write.

FAQ

Is the Lucene limit 32,766 or 32,767?

32,766 bytes is the maximum term length in Lucene's index writer; error messages say “max length 32766”. 32,767 is the signed 16-bit maximum that sits right next to it.

Does ignore_above protect me from the Lucene limit?

ignore_above counts characters, not bytes. A 10,000-character value of 4-byte emoji is 40,000 bytes, so set it conservatively (e.g. 8,191 or lower) — and note that newer columnar index modes behave differently.

How many characters fit in VARCHAR(255) utf8mb4?

255 characters; MySQL VARCHAR lengths are in characters, but the bytes (up to 1,020) count toward row and index limits.
