Characters vs bytes vs code units

“How long is this text?” has at least four correct answers. Knowing which one a system uses is the difference between a post that fits and one that's rejected.

“é” can be stored as one precomposed code point or as “e” plus a combining accent — same look, different length.

The four lengths

1. Visible characters (grapheme clusters)

What a human counts. A flag, a skin-toned thumbs-up or a family emoji is one grapheme even though it's built from several code points. Bluesky counts graphemes; so does our character counter.

2. Code points

Unicode assigns every character a number (U+0041 is “A”, U+1F600 is 😀). Python's len() counts code points. Combining marks and emoji modifiers are separate code points.

3. UTF-16 code units

JavaScript ("😀".length === 2), Java, C#, Windows and Excel count 16-bit units. Characters beyond U+FFFF — most emoji — take two units (a “surrogate pair”). That's why LinkedIn and many web forms count an emoji as 2.

4. UTF-8 bytes

The web's dominant encoding uses 1 to 4 bytes per code point. Databases, file systems, network protocols and search engines usually limit bytes: Lucene's 32,766, S3 object keys' 1,024, DNS, cookies, push payloads. Measure with the byte counter.

Then there are special counts

  • X weighs characters: most Latin text counts 1, while CJK and emoji count 2, and every URL is 23.
  • SMS uses a 7-bit alphabet; leaving it switches the whole message to UCS-2 (details).
  • Google Ads counts double-width (CJK) characters as 2.
  • AI models count tokens (details).

How to count correctly in code

// JavaScript
[...new Intl.Segmenter(undefined, {granularity: 'grapheme'}).segment(s)].length // graphemes
[...s].length                                                                 // code points
s.length                                                                      // UTF-16 units
new TextEncoder().encode(s).length                                            // UTF-8 bytes

# Python
len(s)                    # code points
len(s.encode('utf-8'))    # UTF-8 bytes
len(s.encode('utf-16-le')) // 2   # UTF-16 units
# graphemes: use the third-party "regex" module:  len(regex.findall(r'\X', s))

Rules that prevent bugs

  1. Validate with the same unit the destination enforces.
  2. Normalize to NFC before counting and storing, so “é” is always one code point.
  3. Truncate on grapheme boundaries for anything a person reads.
  4. Size database columns and indexes in bytes, assuming up to 4 per character.
