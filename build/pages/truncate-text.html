Truncation done right

Naive truncation — text.slice(0, 60) — causes three classic bugs: it cuts words in half, it splits emoji into broken “�” symbols, and in byte-limited systems it can slice a multi-byte UTF-8 character and produce invalid data. This tool works on whole grapheme clusters, measures the ending (an ellipsis is a character too), and backs up to the last space when “cut at a word boundary” is on.

Truncate, or rewrite?

For search titles, ad headlines and push notifications, a rewritten line almost always beats an ellipsis. Truncation is best for previews, database columns and logs. See 12 ways to write to fit.

Code snippets

// JavaScript — grapheme-safe character truncation
const seg = new Intl.Segmenter(undefined, {granularity: 'grapheme'});
function truncate(s, max, end = '…') {
  const g = [...seg.segment(s)].map(x => x.segment);
  return g.length <= max ? s : g.slice(0, max - 1).join('').trimEnd() + end;
}

# Python — truncate to N UTF-8 bytes without breaking a character
def truncate_bytes(s, n):
    return s.encode('utf-8')[:n].decode('utf-8', 'ignore')

The Python one-liner is safe for code points but can still split an emoji sequence (e.g. a skin-tone modifier). For user-facing text, segment by graphemes first.
